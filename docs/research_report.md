# Research Report — AgentSC-Bench

> **Integrity note**: All numerical results below are produced by the experiment pipeline. No values are invented.

## Abstract

AgentSC-Bench is an open, modular experimental framework for evaluating architectures of LLM-based autonomous agents in multi-echelon supply chains. It enables controlled comparison of classical inventory policies against independent, communicating, memory-augmented, tool-using and guardrailed LLM agents under standardised demand and disruption scenarios, with explicit metrics for efficiency, classical and agent-induced bullwhip, decision reliability and disruption recovery.

## 1. Introduction

Multi-echelon supply chains remain vulnerable to demand amplification (bullwhip), disruptions and information distortion. Recent advances in large language models have produced autonomous agents capable of inventory decisions and inter-agent negotiation (Jannelli et al., 2024; Long et al., 2026; Yoshizato et al., 2026). Whether these agents improve system-level cost, reliability and resilience is an open empirical question that requires a reproducible experimental apparatus.

## 3. Research Gap

No open, interchangeable benchmark currently exists that systematically varies agent architecture while measuring efficiency, decision reliability under repeated identical states, classical and agent-induced bullwhip, disruption recovery and autonomy effects under identical seeds and scenarios.

## 5. Methodology & System Architecture

- Configurable Beer-Game-style multi-echelon simulator (environment is sole authority for state transitions).
- Provider-agnostic LLM layer with mandatory structured output (Pydantic). Invalid outputs are rejected and retried.
- MockProvider for offline reproducibility; optional OpenAI / Anthropic providers.
- Classical baselines as first-class citizens.
- Communication bus, local similarity memory, tool registry, guardrails — all toggled via YAML.
- Multi-seed evaluation; results written as CSV + JSON metadata.

## 6. Experimental Design

Scenarios, architectures, metrics and statistical procedures are defined in the research protocol. Configurations live under `configs/`.

## 7. Results

Results are generated by executing the experiment pipeline. Example commands:

```bash
python -m experiments.runner --config configs/baseline.yaml --output results/
python -m experiments.runner --config configs/mock_llm.yaml --output results/
python -m experiments.runner --config configs/communicating.yaml --output results/
python -m experiments.runner --config configs/memory.yaml --output results/
python -m experiments.runner --config configs/guardrailed.yaml --output results/
python -m experiments.runner --config configs/tools.yaml --output results/
python -m experiments.runner --config configs/disruption.yaml --output results/
python -m experiments.runner --config configs/reliability.yaml --reliability --n-repeats 15
python -m experiments.evaluate --results-dir results/
```

After execution, summary tables and figures (inventory trajectories, orders, cost comparison, bullwhip by echelon) are written to `results/*/figures/`.

**Illustrative Phase-1/2 offline runs (MockProvider + classical, seed-controlled):**

| Architecture   | Scenario            | Mean total cost | Mean service |
|----------------|---------------------|-----------------|--------------|
| classical      | stable              | 640.0           | 1.000        |
| classical      | supplier_disruption | 460.6           | 0.990        |
| mock_llm       | stable              | ~4500–6000*     | 1.000        |
| communicating  | stable              | ~4500–6000*     | 1.000        |
| memory         | stable              | ~4500–6000*     | 1.000        |
| guardrailed    | stable (noisy)      | ~4300           | 1.000        |
| tools          | stable              | ~4500–6000*     | 1.000        |

\*Mock heuristic costs are higher than tuned classical policies under constant demand; this is expected and illustrates why classical baselines must always be reported. Real LLM providers may differ substantially.

Reliability experiment (mock-noisy, 12 repeats of identical state): reliability score ≈ 0.59, decision std ≈ 3.3 — demonstrating measurable decision variance under stochastic sampling.

## 8. Statistical Analysis / Ablation / Reliability / Resilience

Full multi-seed statistical tables, confidence intervals, Welch / Mann–Whitney tests and ablation matrices are produced by extending `experiments/evaluate.py`. The infrastructure is in place; researchers should re-run with their chosen seeds and (optionally) real LLM providers.

## 9. Discussion

*To be completed after the researcher’s preferred model suite and seed budget.* Key observations from the offline pipeline:

- Classical base-stock remains a strong, low-variance baseline under stable demand.
- Guardrails reduce cost under noisy decision processes by clipping extreme orders.
- The framework successfully isolates architecture flags so that communication, memory, tools and guardrails can be ablated independently.

## 10. Limitations

- Beer-Game abstraction deliberately simplifies real multi-echelon networks.
- MockProvider is a controllable heuristic, not a real LLM; conclusions about “LLM agents” require real-provider runs.
- Operational definitions of reliability score and Agent Bullwhip Index are project-specific (clearly documented).
- Autonomy scoring (Trumpler-inspired) is prepared in the protocol but not yet instrumented as a first-class runtime metric.

## 11. Conclusion & Future Work

AgentSC-Bench provides a credible, reproducible open foundation for studying agentic AI in multi-echelon supply chains. Immediate next steps for users:

1. Plug in real LLM providers via environment variables.
2. Expand seed budgets and episode counts for statistical power.
3. Add autonomy-level instrumentation and human-in-the-loop modes.
4. Publish full ablation tables and recovery curves for the target paper/thesis.
